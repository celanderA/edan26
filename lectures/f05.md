## Detacting write completion

- Consider a write to a memory location which is replicated in some caches
- How can the writgin processer know when its safe to proceed?
- the write rewuest is sent to the memory where the data is located.
- THe memory knows which caches have a copy (recall from a previoud lecture this infomation is stored in a directory, eg as a bit vector)
- The memory then sends either updates or invalidations to the other caches.
- The receving cahes then must acknowledge they have received the invalidation mesage from memory
- The acknowledgement is typically sent to the memory and then when all ackledgements have been received, message is sent to the writing processor (actually, its cache) to tell it the write has comletes
- After that the processor can proceed.

  ## Write atomicity updates protocols
  - Recall that in a write update protocol, instead of invalidating other copies, new values are sent to the caches which replicate the value.
  - So A is sent to T2 and to T3
  - While its tempting to read A for T2 ists not permitted to.
  - In writing update, the updates are done in two phases. First is the data sent, and all CPUS acknowledge thay have received it. Second each CPU is sent a messge that it may read the neew data.
  - There are other problem with write updates as well, for instance updates may be sent to CPUS which no longer are intrested in the variable, thus wasting network traffic.

  ## Optimixig compilers and explicit parallel codes
  - We have now seen the restictions on hardware so that is does not reorder memory accessed and this violate SC.
  - The same restictions must be put on opitmizing compilers
  - teh compiler must preserve "source code order" of all memory accesses to variables which may be shared -- but not the order of stack accesse or other data known to be private to the thread
  - Examples of optimizations which cannot (in genereal) be used:
    - Register allocation
    - Code motion out of loops
    - Loop reordering
    - Software pipelining

- Its easy to imagine that these restrictions will slow down SC.
- Before C11 the soltion for C ha often been to compile code for uniprocessors and use the volatile quilifier for shared data.
