## Detacting write completion

- Consider a write to a memory location which is replicated in some caches
- How can the writgin processer know when its safe to proceed?
- the write rewuest is sent to the memory where the data is located.
- THe memory knows which caches have a copy (recall from a previoud lecture this infomation is stored in a directory, eg as a bit vector)
- The memory then sends either updates or invalidations to the other caches.
- The receving cahes then must acknowledge they have received the invalidation mesage from memory
- The acknowledgement is typically sent to the memory and then when all ackledgements have been received, message is sent to the writing processor (actually, its cache) to tell it the write has comletes
- After that the processor can proceed.

## Optimizing SC in hardware

- Data prefetech can either fetch data in shared or exclustion mode
- By prefetching data in exclutsive mode, the long delays of waiting for writes to conmplete can possiblty be reduce or eliminated
- Since exclutsive mode prefetching invalidates other copies it can also increase the cache miss rate.
- Somewhat more complexe cache coherence protocols can moitor the sharing behavior and determine that is probably is a good idea to grant exclusive ownership directly instead of onlt a shared copy which is then likely follow by an ownership request
- In superscaler processor it can be beneficial to permit speculative executed instructions (the read and subsequent instructiosn) are kille rand the read is re-executed

  1. write to read program order ot different addresses
